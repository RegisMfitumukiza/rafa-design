> **Purpose:** This document defines the vision, scope, and philosophy of the project. It does not define implementation details. Technical architecture, coding standards, and design tokens are documented separately and must be followed in conjunction with this overview.

# Project Overview

## Vision

RAFA Design is a premium digital platform for an architecture and design studio.

The website is designed to communicate the studio's philosophy through carefully crafted visual storytelling rather than traditional marketing.

Instead of overwhelming visitors with large amounts of text, the experience relies on:

- Architecture
- Photography
- Motion
- Composition
- Typography
- White space
- Editorial layouts
- Interaction

Every page should feel calm, deliberate, and immersive.

The website should encourage exploration rather than explanation.

---

# Project Goals

The primary objectives are:

- Showcase architectural projects beautifully.
- Present the studio's philosophy and design approach.
- Create an immersive digital experience.
- Build credibility through craftsmanship.
- Allow visitors to discover projects naturally.
- Maintain exceptional performance despite rich interactions.
- Provide an intuitive navigation experience.
- Build a scalable foundation for future growth.

---

# Design Philosophy

The website should never feel like a traditional corporate website.

Instead, it should feel like a digital exhibition.

The interface should disappear, allowing architecture and imagery to become the primary focus.

Content should breathe.

Motion should guide.

Typography should create rhythm.

Photography should tell the story.

Every visual decision must support the architecture instead of competing with it.

---

# User Experience Principles

The experience should feel:

- Calm
- Elegant
- Minimal
- Sophisticated
- Cinematic
- Intentional
- Premium
- Editorial

The user should never feel overwhelmed.

Instead of presenting everything immediately, the website should reveal information progressively through interaction and scrolling.

---

# Design Inspiration

The project takes inspiration from internationally recognized architecture and design studios, not by copying their interfaces, but by understanding their design philosophy.

Inspirations include ideas commonly found in studios such as:

- BIG (Bjarke Ingels Group)
- Snøhetta
- OMA
- Foster + Partners
- Herzog & de Meuron
- Studio Gang
- Kengo Kuma & Associates

The objective is to learn from their approach to visual communication while creating an original identity for RAFA Design.

No layouts, animations, or interactions should be directly replicated.

# Website Structure

The website is a multi-page experience.

The landing page acts as an introduction rather than a traditional marketing homepage.

Additional pages provide deeper exploration of the studio and its work.

Expected pages include:

- Home
- Projects
- Individual Project
- Studio
- Services
- Process
- Journal
- Careers
- Contact
- Privacy Policy

Additional pages may be added as the project evolves.

---

# Content Strategy

Content should be concise.

Architecture should remain the primary focus.

Large blocks of marketing text should be avoided.

Instead, combine:

- High-quality imagery
- Architectural renders
- Videos
- Motion
- Minimal copy
- Clear hierarchy
- Editorial layouts

Every sentence should have purpose.

---

# Motion Philosophy

Motion is an integral part of the experience.

Animations should:

- Guide attention.
- Improve spatial understanding.
- Reveal information progressively.
- Reinforce storytelling.
- Never distract from the content.

Motion should feel smooth, natural, and understated.

The objective is refinement rather than spectacle.

---

# Three.js Philosophy

Three.js should enhance the experience rather than dominate it.

**Status (2026-08-11):** the Three.js layer was removed — it existed only to back the deleted homepage hero. The philosophy below applies only if a future story reintroduces Three.js.

Potential uses include:

- Interactive hero scenes
- Subtle environmental effects
- Architectural models
- Particle systems
- Scroll-linked visual storytelling
- Experimental transitions

Three.js should only be used when it adds meaningful value.

Performance always takes priority over visual complexity.

---

# Performance Goals

Despite cinematic interactions, the website should remain highly optimized.

Primary goals:

- Fast initial load
- Smooth scrolling
- Responsive interactions
- Efficient image loading
- Lazy loading where appropriate
- GPU-friendly animations
- Excellent Core Web Vitals

Performance is considered part of the design.

---

# Accessibility Goals

Accessibility is a core requirement.

The project should support:

- Semantic HTML
- Keyboard navigation
- Screen readers
- Focus visibility
- Color contrast
- Reduced motion preferences
- Responsive typography

Accessibility should never be treated as an afterthought.

# Development Principles

Every implementation should prioritize:

1. Simplicity
2. Maintainability
3. Scalability
4. Performance
5. Accessibility

7. Consistency

# Definition of Success

The project is successful when it achieves the following:

- Communicates the studio's identity effectively.
- Creates a memorable first impression.
- Encourages visitors to explore projects.
- Maintains a consistent design language.
- Delivers smooth interactions on all devices.
- Achieves excellent performance metrics.
- Remains easy to extend and maintain.
- Serves as a production-ready foundation for future growth.

# Guiding Principle

Every design decision should answer one question:

> **Does this improve the experience of discovering architecture?**

If the answer is no, it should not be implemented.
